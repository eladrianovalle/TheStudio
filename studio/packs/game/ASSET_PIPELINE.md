# The game pack's asset pipeline

**This document applies only if this repository's `.studio/implementation_loop.toml` has a
`[packs.game]` table.** If it has none, everything here is inert: the repository has not opted into
the game pack, and nothing below changes how it already works.

The game pack is the art department's rulebook. Studio ships it; the repository fills in the two
things only it knows: which ways of making assets it allows, and the command that measures its
assets. Studio then compares every measurement to its limit and fails the check when one is out of
bounds, so no game re-implements those comparisons.

## The three routes

A route is the way an asset gets made. The repository lists the routes it allows, and an asset made
any other way fails the check.

- **code-built**: the asset is generated by code in this repository. It suits anything you could
  measure with a ruler: props, buildings, procedural generators.
- **generated**: a model or texture generator made it. It suits organic shapes that code builds badly.
- **hand-authored**: a person made it in an editor and the file is committed.

Only **hand-authored** may put binary asset files in git: images, models, fonts and audio. When a
repository's routes leave hand-authored out, any such file git would commit fails the check, by its
extension (`.png`, `.glb`, `.wav` and the rest of the list in `pack.json`), upper or lower case.
Ignored files never count, and a file you deleted counts as gone.

## Measurements first

Before you build an asset, write down what it has to measure: its size against the measurements of
the thing it sits beside, its triangle budget, and for an animation the frames that must line up.
Then build it, and let the asset command report against those numbers. Code cannot check that the
numbers came first, so this rule rests on you. An asset sized after the fact tends to be sized to
whatever came out.

## What each kind must report

| Kind | Metric | What it measures |
|---|---|---|
| `mesh` | `triangles` | the triangle count, against the budget |
| `mesh` | `part_gap` | the largest gap between parts that should sit flush |
| `mesh` | `extent` | the largest side of the bounding box, against the measurements written before building |
| `animation` | `foot_slide` | how far a planted foot moves |
| `animation` | `loop_seam` | the difference between a loop's first and last frame |
| `animation` | `below_floor` | how far anything dips under the floor |
| `animation` | `stretch` | the longest edge in a test pose relative to the rest pose |

## The report

The repository's asset command prints the report as JSON on stdout. Everything else it prints goes
to stderr, because anything else on stdout makes the report unreadable.

```json
{"assets": [{"id": "hero_walk", "kind": "animation", "route": "code-built",
  "metrics": {"foot_slide": {"value": 0.8, "max": 1.0}, "loop_seam": {"value": 0, "max": 0},
              "below_floor": {"value": 0.0, "max": 0.01}, "stretch": {"value": 1.02, "min": 0.98, "max": 1.05}}}]}
```

- `value` is required: a finite int or float, and a bool does not count.
- Each metric needs a `max`, a `min`, or both. The limits live in the repository's own code, so
  nothing is declared twice.
- Metrics beyond the required ones are checked the same way. Unknown keys are ignored.
- The asset command must leave the working tree unchanged, apart from ignored paths. Write any
  scratch files under an ignored folder.

## Running the check

```bash
python .studio/source/run_phase.py check-packs
```

It runs from the top of the git repository, reads `.studio/implementation_loop.toml` (or the file
`--config` names), runs each declared department's asset command, and judges what the command
printed. Each problem is printed as `game.art: <problem>`, followed by the path of this document.

| Exit | Meaning |
|---|---|
| 0 | Every report is within its limits, or no pack is declared. |
| 1 | At least one problem: the command failed, changed the tree, printed a bad report, or a binary asset is tracked without the route that allows one. |
| 2 | Nothing could be checked: the `[packs]` table is invalid, or this is not a git repository. |

Every run saves the command's output and every problem it printed to
`<git-dir>/studio/pack-reports/game-art.json`. The git directory is per-worktree and git never shows
it as an untracked file.

## At the `/forge` gate

Declaring the pack is enough to turn the check on: every `/forge` unit runs `check-packs` as one more
static check, and a failure fails the unit the way a failing linter does. Nothing in `static_checks`
switches it off; only removing the `[packs.game]` table does. The check runs while the writer's change is still uncommitted, which is why the asset command
must leave the working tree unchanged.

Who decides the verdict:

> Studio code runs `check-packs` only on the portable host, and only on the writer's change. On the
> native workflow the verdict is the writer's own report, and a missing report passes. On both
> paths, changes the editor makes are not re-checked.

## The look pass

Numbers catch a model over budget. They do not catch a model that looks wrong. In the look pass a
person is the final judge: agents capture images with `[gate] observe_command` and show them, and
the person says whether the asset is right. There is no sign-off field, because an agent could write
one itself.

## Declaring the pack

Paste this into `.studio/implementation_loop.toml` and change the two values:

```toml
[packs.game.art]
asset_command = "node tools/measure-assets.mjs"
routes = ["code-built"]
```

`routes` is the routes this repository allows, from `code-built`, `generated` and `hand-authored`.
Any other key in the table is refused.
